# Гиря 🏋️

> Репозиторий: https://github.com/HernoBeliEzh/-girya-

**Гиря** — мост между сайтом [whizi.io](https://whizi.io) и любым OpenAI-совместимым клиентом, в первую очередь [OpenCode](https://opencode.ai). Это программа на PowerShell: она поднимает локальный сервер, выдаёт **единый API-ключ формата OpenAI** и проксирует запросы в whizi.io под вашим аккаунтом (через cookie).

Простыми словами: вы платите за один аккаунт whizi.io (GPT, Claude, Gemini и др. в одном месте) и пользуетесь всеми моделями прямо из OpenCode как обычным OpenAI API — **включая полноценный режим агента** (чтение/запись файлов, запуск команд).

## Как это работает

У whizi.io **нет официального публичного API** — это веб-сервис для людей. Гиря повторяет те же запросы, что делает браузер:

1. **Аутентификация — Clerk** (`clerk.whizi.io`). По вашему cookie (главное — `__client`) Гиря получает короткоживущий JWT (~60 секунд) и сама его обновляет.
2. **Создание чата** — `POST /api/create-chat` (whizi не принимает произвольный chat_id).
3. **Отправка сообщения** — `POST /api/add-message?stream=true`, ответ читается из SSE-потока.
4. **OpenAI-обёртка** — всё это отдаётся клиенту как стандартный `/v1/chat/completions`.
5. **Режим агента** — поскольку whizi не умеет нативный tool-calling, Гиря **эмулирует** его: передаёт модели описания инструментов OpenCode, парсит её ответ и возвращает в формате OpenAI `tool_calls`.

```
OpenCode ──HTTP──▶ Гиря (localhost:8788) ──▶ Clerk (токен) ──▶ whizi backend ──▶ модель
   ▲                                                                                │
   └──────────────── OpenAI-ответ / tool_calls ◀───────────── разбор SSE ◀──────────┘
```

## Возможности

- 🔑 **Единый OpenAI-ключ** формата `sk-girya-...` для всех клиентов.
- 🌐 **Локальный сервер**: `/v1/models` и `/v1/chat/completions` (стриминг SSE).
- 🤖 **Полноценный OpenCode-агент** — эмуляция tool-calling (чтение/запись файлов, команды).
- 👤 **Аккаунты whizi**: добавить, удалить, сменить активный, показать, обновить cookie.
- 🔒 **Cookie шифруется** (Windows DPAPI) — на диск в открытом виде не попадает.
- 🔁 **Авто-обновление токена и cookie** (Clerk-ротация подхватывается автоматически).
- 🧩 **Несколько моделей**, переключение из CLI/меню; веб-поиск вкл/выкл.
- 🖥️ **Меню в PowerShell** + полноценный CLI + быстрая установка одной строкой.

## Установка

### Быстрая установка (одной строкой)

Самый простой способ. Открой **PowerShell** и вставь:

```powershell
irm https://raw.githubusercontent.com/HernoBeliEzh/-girya-/main/bootstrap.ps1 | iex
```

**Что произойдёт по шагам:**
1. Скрипт проверит, установлен ли `git` (если нет — даст ссылку на установку).
2. Склонирует репозиторий в `%LOCALAPPDATA%\Programs\Girya`
   (это путь вида `C:\Users\ИМЯ\AppData\Local\Programs\Girya`).
3. Запустит `Install.ps1`, который:
   - создаст конфиг и единый API-ключ в `%APPDATA%\Girya\config.json`;
   - спросит, добавить ли аккаунт сейчас (можно пропустить и сделать позже);
   - добавит команду **`girya`** в PATH.
4. После установки **перезапусти терминал**, чтобы команда `girya` стала доступна.

> **Если `irm ... | iex` ругается на политику выполнения** — запусти так:
> ```powershell
> powershell -ExecutionPolicy Bypass -Command "irm https://raw.githubusercontent.com/HernoBeliEzh/-girya-/main/bootstrap.ps1 | iex"
> ```

> **Если нет git** — поставь его (<https://git-scm.com/download/win>), закрой и открой PowerShell заново, повтори команду.

Повторный запуск той же команды **обновит** уже установленную копию (`git pull`).

### Обычная установка

```powershell
# 1. Клонируй репозиторий
git clone https://github.com/HernoBeliEzh/-girya-.git
cd -girya-

# 2. Запусти установку (создаст конфиг, ключ, добавит команду 'girya')
powershell -ExecutionPolicy Bypass -File Install.ps1
```

После установки доступна команда **`girya`** (перезапусти терминал) либо двойной клик по **`Гиря.cmd`** в папке проекта.

## Настройка аккаунта: что и где брать

Гире нужны **2 обязательных значения** (Cookie и User ID) и одно необязательное (Session ID). Всё берётся за один заход в DevTools браузера.

> **Подготовка:** открой [whizi.io](https://whizi.io), войди в аккаунт, зайди в чат.
> Нажми **F12** → вкладка **Network (Сеть)** → отправь в чате любое сообщение (например `привет`).
> В списке запросов появятся нужные строки.

### 🔑 1. Cookie (самое важное — тут чаще всего ошибаются)

Нужен cookie с домена **`clerk.whizi.io`**, в котором есть токен **`__client`**.

> ⚠️ **Типичная ошибка:** копируют cookie со страницы `whizi.io` (там `__session`, `clerk_active_context`).
> Это **НЕ то** — `__session` живёт 60 секунд. Нужен именно **`__client`** с домена **clerk.whizi.io** (он долгоживущий).

**Способ А — через «Copy as cURL» (рекомендуется, без ошибок):**
1. В **Network** найди запрос к **`clerk.whizi.io`** с путём, оканчивающимся на **`/touch`** или **`/tokens`**.
2. **Правый клик** по нему → **Copy → Copy as cURL** (любой вариант — bash/cmd).
3. В скопированном тексте найди кусок `-b '...'` (или `-H 'cookie: ...'`) — это и есть cookie. Выглядит так:
   ```
   __client=eyJhbGci...длинный токен...; __client_uat=1781632102; __cf_bm=...; _cfuvid=...
   ```
4. Скопируй **всю строку cookie** целиком.

**Способ Б — через вкладку Application:**
1. F12 → **Application (Приложение)** → слева **Cookies** → выбери **`https://clerk.whizi.io`**.
2. Найди строку **`__client`** и скопируй её длинное **Value** (начинается с `eyJ...`).
3. Желательно так же скопировать **`__cf_bm`** (помогает обходить защиту Cloudflare).
4. Собери одну строку:
   ```
   __client=ЗНАЧЕНИЕ_CLIENT; __cf_bm=ЗНАЧЕНИЕ_CFBM
   ```

### 🆔 2. User ID (UUID пользователя whizi)

1. В **Network** найди запрос **`add-message`** → вкладка **«Полезная нагрузка» (Payload)**.
2. Скопируй значение поля **`user_id`**. Выглядит как UUID:
   ```
   cef6f4c5-28f6-41c9-8cb6-9dfdf568077b
   ```

> Это **не** Clerk-ID (`user_3FEF...`), а внутренний UUID whizi. Берётся именно из тела `add-message`.

### 🪪 3. Session ID (необязательно)

Обычно Гиря определяет его сама. Если нужно вручную — это `sess_...` из URL запроса к Clerk:
```
https://clerk.whizi.io/v1/client/sessions/sess_3FEF0yVM5h5eq5dpThFc6trpb2t/tokens?...
                                            └──────────── это Session ID ────────────┘
```

### Куда всё это вводить

**Через меню** (проще): запусти `girya` → пункт **2) Добавить аккаунт** и вставляй значения по подсказкам.

**Через CLI** (одной командой):
```powershell
girya add -Name main -Cookie "__client=eyJ...; __cf_bm=..." -UserId "cef6f4c5-28f6-41c9-8cb6-9dfdf568077b"
```

Имя аккаунта (`-Name`) — любое, для себя (например `main`, `работа`). Можно добавить несколько аккаунтов и переключаться.

> Cookie — это ваш ключ доступа. Никому не показывайте. Гиря хранит его в зашифрованном виде (DPAPI).

## Интеграция с OpenCode

1. Запусти сервер: `girya serve` (оставь окно открытым — пока оно работает, мост активен).
2. Получи готовый блок настройки: `girya opencode` — он выведет JSON **с уже вставленным ключом и адресом**.
3. Открой (или создай) конфиг OpenCode:
   ```powershell
   mkdir "$env:USERPROFILE\.config\opencode" -Force
   notepad "$env:USERPROFILE\.config\opencode\opencode.json"
   ```
4. Вставь блок из `girya opencode`. Должно получиться так:

```json
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "girya": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "Гиря (whizi)",
      "options": {
        "baseURL": "http://127.0.0.1:8788/v1",
        "apiKey": "sk-girya-ВАШ_КЛЮЧ"
      },
      "models": {
        "openai gpt-5.5":                { "name": "openai gpt-5.5", "tool_call": true },
        "anthropic claude-sonnet-4.6":   { "name": "anthropic claude-sonnet-4.6", "tool_call": true },
        "google gemini-3.1-pro-preview": { "name": "google gemini-3.1-pro-preview", "tool_call": true }
      }
    }
  }
}
```

5. Запусти `opencode`, выбери провайдера **Гиря (whizi)** и модель (например `openai gpt-5.5`). Пиши задачи — модель будет читать/писать файлы и запускать команды.

> **Если у вас уже есть `opencode.json` / `opencode.jsonc`** — не заменяйте файл целиком, а **добавьте только блок `"girya": { ... }`** внутрь существующего объекта `"provider"` (через запятую после других провайдеров).

**Проверка вручную** (PowerShell):
```powershell
curl http://127.0.0.1:8788/v1/chat/completions `
  -H "Authorization: Bearer sk-girya-ВАШ_КЛЮЧ" `
  -H "Content-Type: application/json" `
  --data-raw '{ "model": "openai gpt-5.5", "messages": [ { "role": "user", "content": "2+2?" } ] }'
```
Должен вернуться JSON с ответом `4`.

## Меню и CLI

**Меню** (`girya`):
```
 1) Показать аккаунты          7) Показать API-ключ / Base URL
 2) Добавить аккаунт (cookie)  8) Перегенерировать API-ключ
 3) Удалить аккаунт            9) Настройка OpenCode
 4) Сменить активный аккаунт   c) Показать конфигурацию
 u) Обновить cookie аккаунта   s) Запустить локальный сервер
 5) Сменить модель             0) Выход
 6) Веб-поиск (вкл/выкл)
```

**CLI-команды:**

| Команда | Описание |
|---|---|
| `girya` / `girya menu` | Интерактивное меню |
| `girya add -Name <имя> -Cookie <cookie> -UserId <uuid> [-SessionId sess_...]` | Добавить аккаунт |
| `girya cookie [-Name <имя>] -Cookie <cookie>` | Обновить cookie аккаунта (когда устарел) |
| `girya remove -Name <имя>` | Удалить аккаунт |
| `girya use -Name <имя>` | Сделать аккаунт активным |
| `girya list` | Показать аккаунты |
| `girya model [-Model "<имя>"]` | Показать / сменить модель по умолчанию |
| `girya websearch [-State on\|off]` | Показать / переключить веб-поиск |
| `girya serve [-ListenHost <addr>] [-Port <n>]` | Запустить локальный сервер |
| `girya key [-Regenerate]` | Показать / пересоздать API-ключ |
| `girya config` | Показать конфигурацию и путь к ней |
| `girya opencode` | Показать готовый блок настройки OpenCode |

## Модели и веб-поиск

Модели задаются в `whizi.models` (формат whizi: `"провайдер модель"`). По умолчанию:
```
openai gpt-5.5
anthropic claude-sonnet-4.6
google gemini-3.1-pro-preview
```

- Сменить модель по умолчанию: `girya model -Model "anthropic claude-sonnet-4.6"` (или пункт меню «Сменить модель»).
- В OpenCode модель выбирается из списка провайдера «Гиря».
- **Веб-поиск**: `girya websearch -State on|off`. Включён по умолчанию, но **в режиме агента (с инструментами) автоматически отключается** — иначе он мешает строгому формату вызовов инструментов.

Точные имена доступных моделей можно подсмотреть на самом whizi.io (выпадающий список выбора модели) и добавить в `%APPDATA%\Girya\config.json` → `whizi.models`.

## Как обновить код / две копии

⚠️ Важно понимать: после установки существуют **две копии**:
- **рабочая копия**, из которой запускается команда `girya` —
  `%LOCALAPPDATA%\Programs\Girya` (при быстрой установке) или папка, где вы делали `git clone`;
- любая другая папка, которую вы редактируете.

Команда `girya` всегда использует ту копию, путь к которой прописан в её лаунчере
(`%APPDATA%\Girya\bin\girya.cmd`). Поэтому правки в другой папке **не повлияют**, пока вы их туда не скопируете/не подтянете.

**Обновить рабочую копию из GitHub:**
```powershell
git -C "$env:LOCALAPPDATA\Programs\Girya" pull
```
или просто повтори быструю установку (`irm ... | iex`).

> После любого обновления кода **перезапусти `girya serve`** — запущенный сервер держит старый код в памяти.

## Устранение неполадок

**`Clerk отклонил запрос токена (HTTP 401/403)`**
Cookie устарел. Самая частая причина — **просрочен `__cf_bm`** (Cloudflare, живёт ~30 минут) или вы пользуетесь whizi в браузере параллельно (он «прокручивает» `__client`).
Решение:
1. Закрой whizi во всех вкладках браузера.
2. Возьми свежий `__client` (+ `__cf_bm`) — см. [раздел про cookie](#-1-cookie-самое-важное--тут-чаще-всего-ошибаются).
3. Обнови: `girya cookie -Cookie "__client=...; __cf_bm=..."`
4. Перезапусти `girya serve`.
При активном использовании Гиря сама обновляет `__cf_bm` из ответов — проблема возникает в основном после долгого простоя.

**`Не удалось определить sessionId Clerk`**
В cookie нет `__client` или нет активной сессии. Убедись, что взял cookie именно с `clerk.whizi.io`. Можно задать Session ID вручную: `girya add ... -SessionId sess_...`.

**Модель отвечает обобщённо («Чем помочь?») и не выполняет задачу**
Скорее всего вы запускаете **старую копию** кода — обнови рабочую копию (см. [выше](#как-обновить-код--две-копии)) и перезапусти `girya serve`.

**OpenCode: `Type validation failed ... tool_calls`**
Старая версия Гири. Обнови код и перезапусти сервер.

**`connection refused` в OpenCode**
Не запущен `girya serve`, либо другой порт. Проверь порт: `girya config`.

**Отладка**
Включи лог: в `%APPDATA%\Girya\config.json` поставь `"debug": true`, перезапусти сервер. Последний запрос/ответ запишется в `%APPDATA%\Girya\debug.log`. Не забудь потом выключить (`"debug": false`).

## Как это устроено внутри

Конфигурация (`%APPDATA%\Girya\config.json`, раздел `whizi`) — всё уже настроено:
```json
"whizi": {
  "origin": "https://whizi.io",
  "clerkBase": "https://clerk.whizi.io",
  "clerkApiVersion": "2025-11-10",
  "clerkJsVersion": "5.125.13",
  "clerkTemplate": "",
  "backendBase": "https://backend.whizibackend.workers.dev",
  "chatPath": "/api/add-message?stream=true",
  "createChatPath": "/api/create-chat",
  "defaultModel": "openai gpt-5.5",
  "models": [ "openai gpt-5.5", "anthropic claude-sonnet-4.6", "google gemini-3.1-pro-preview" ],
  "userType": "user",
  "webSearch": true
}
```

Ключевые места в коде:
- `Get-WhiziToken` ([`src/Whizi.ps1`](src/Whizi.ps1)) — получение и кэш Clerk-JWT, авто-сохранение ротации cookie.
- `New-WhiziChat` — создание чата (`create-chat`).
- `Build-WhiziRequestBody` — сборка тела `add-message`; в режиме агента ставит инструменты и задачу **в начало** content (whizi обрезает длинный content по началу), а системный промпт OpenCode — обрезанным в конец.
- `Build-GiryaToolsPrompt` / `Get-GiryaToolCalls` — эмуляция tool-calling.
- `Get-WhiziEvent` — разбор SSE (`aiStream` склеивается, `finalMessage` — итог, `aiReasoning`/служебное игнорируется).
- `Server.ps1` — OpenAI-совместимый HTTP-сервер (`/v1/models`, `/v1/chat/completions`, стрим и tool_calls).

Эндпоинты сервера:

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/` | Страница статуса |
| `GET` | `/v1/models` | Список моделей (формат OpenAI) |
| `POST` | `/v1/chat/completions` | Чат (поддержка `stream`, `tools`) |

Авторизация — заголовок `Authorization: Bearer <ключ Гири>`.

Структура проекта:
```
Гиря/
├─ Install.ps1        # установка и первичная настройка
├─ bootstrap.ps1      # быстрая установка одной строкой
├─ Гиря.cmd           # запуск меню двойным кликом
├─ README.md · LICENSE · .gitignore
├─ examples/opencode.json
└─ src/
   ├─ Common.ps1      # конфиг, пути, ключ, шифрование cookie, JWT-хелперы
   ├─ Accounts.ps1    # управление аккаунтами
   ├─ Whizi.ps1       # адаптер к whizi (Clerk, create-chat, SSE, tool-calling)
   ├─ Server.ps1      # OpenAI-совместимый сервер
   └─ Girya.ps1       # меню и CLI
```

## Ограничения

- **Эмуляция tool-calling.** whizi не поддерживает инструменты нативно. Модель (особенно `openai gpt-5.5`, `anthropic claude-sonnet-4.6`) следует формату хорошо, но **иногда может ошибиться в одном вызове** — OpenCode покажет ошибку инструмента, и модель попробует снова. Это нормальная работа агента.
- **Лимит длины content у whizi.** Очень длинные диалоги/большие файлы обрезаются. Гиря приоритезирует задачу и инструменты, а фон (системный промпт, старые сообщения, большие результаты) урезает.
- **Clerk-ротация и Cloudflare.** Не используйте whizi в браузере параллельно с Гирей и обновляйте cookie при долгом простое.
- whizi.io может изменить внутренний формат запросов — тогда потребуется правка адаптера.

---

## Безопасность

- Cookie шифруется через **DPAPI** и расшифровывается только под вашей учётной записью Windows. В репозиторий он не попадает (хранится в `%APPDATA%\Girya`, плюс `.gitignore`).
- Сервер по умолчанию слушает только `127.0.0.1` (локально). Наружу открывать не рекомендуется.
- Это **неофициальный** инструмент, использующий ваш личный доступ к whizi.io. Соблюдайте условия использования сервиса — автоматизация может им противоречить, ответственность на пользователе.
